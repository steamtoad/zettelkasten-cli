## ADDED Requirements

### Requirement: CHAIN-CHECK-001 — Preflight Diary предшествует любой записи

**Stable ID:** зарезервирован этой дельтой; legacy запись добавляется при проверенной интеграции.

**Статус изменения:** `PROPOSED`, не подтверждение реализации.

zt-diary MUST до создания объекта проверить .last-diary: basename UUID.adoc без путевых сегментов, существующий type=diary, отсутствие уже занятого next у выбранного хвоста. Отсутствующий pointer SHALL приниматься только в начальном хранилище без Diary.

#### Scenario: Pointer указывает на Note

- **GIVEN** существующая .last-diary содержит basename Note
- **WHEN** вызван zt-diary
- **THEN** ERROR DIARY_POINTER_TYPE; все документы, указатель и all-todays сохраняют хеши

#### Scenario: Первая запись

- **GIVEN** нет Diary и .last-diary отсутствует
- **WHEN** вызван zt-diary
- **THEN** создан один Diary без previous, один activity entry и pointer на новый basename

### Requirement: CHAIN-CHECK-002 — Проверка Diary включает граф и хронологию

**Stable ID:** зарезервирован этой дельтой; legacy запись добавляется при проверенной интеграции.

**Статус изменения:** `PROPOSED`, не подтверждение реализации.

zt-check MUST выявлять неверный тип цели, невзаимные previous/next, несколько предыдущих или следующих связей, цикл, разрыв на несколько компонент и pointer не на единственный хвост. Он SHALL проверять неубывание date, допуская несколько записей одной даты.

#### Scenario: Невзаимность и цикл

- **GIVEN** раздельные fixtures содержат A→B без B→A, а также A→B→A
- **WHEN** выполнен checker
- **THEN** оба fixtures отклонены с конкретными кодами и путями

#### Scenario: Две записи одной даты

- **GIVEN** есть взаимная линейная цепочка с равными date и верным pointer
- **WHEN** выполнен checker
- **THEN** цепочка принята; новые даты и UUID не назначаются

### Requirement: CHAIN-CHECK-003 — Memo chains различают основную линию, ветки и примеры

**Stable ID:** зарезервирован этой дельтой; legacy запись добавляется при проверенной интеграции.

**Статус изменения:** `PROPOSED`, не подтверждение реализации.

Continue и checker MUST разбирать цепочки только в рабочем содержимом. Memo SHALL иметь не более одного Следующее memo, каждое продолжение — одно Предыдущее memo; Ветка допускает несколько целей. Проверяются type=memo, взаимность и отсутствие циклов без запрета разрешённых веток.

#### Scenario: Пример не создаёт ветку

- **GIVEN** единственное Следующее memo находится в блоке кода
- **WHEN** создаётся первое реальное продолжение
- **THEN** новая рабочая ссылка называется Следующее memo, а не Ветка

#### Scenario: Ветвление допустимо

- **GIVEN** у Memo есть одна основная линия и две взаимные ветки
- **WHEN** запущен checker
- **THEN** все три продолжения приняты; дубль основной линии отдельно даёт ERROR
