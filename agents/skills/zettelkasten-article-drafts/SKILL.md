# Zettelkasten Article Drafts

## Назначение

Готовить Markdown-черновики статей по материалам личного Zettelkasten и выгружать их в подключённый Obsidian Vault для статей.

## Когда применять

Активировать навык, когда пользователь просит написать или подготовить:

- «Напиши черновик на тему ...»;
- «Напиши черновик статьи на тему ...»;
- «Напиши статью на тему ...»;
- «Подготовь article на тему ...»;
- аналогичный запрос, явно требующий черновик статьи по материалам Zettelkasten.

Не применять для обычного краткого ответа, тематического обзора в чате или создания новой Zettelkasten-заметки, если пользователь не просит статью.

## Локальные пути

Перед работой прочитать `TOOLS.md` активного agent workspace и использовать указанные там пути:

- `Zettelkasten source` — источник заметок;
- `Obsidian article drafts vault` — каталог выгрузки Markdown.

Не изменять файлы Zettelkasten во время подготовки статьи. Записывать только итоговый Markdown-файл в Obsidian Vault.

## Определение темы и заголовка

1. Извлечь тему из запроса пользователя.
2. Использовать предложенную пользователем формулировку темы как точный H1-заголовок статьи.
3. Нормализовать только случайные переносы строк и повторные пробелы внутри темы.
4. Не переименовывать, не украшать и не дополнять заголовок без прямой просьбы.

Пример: тема `Мой Zettelkasten CLI и подход к ведению заметок` должна дать заголовок:

```markdown
# Мой Zettelkasten CLI и подход к ведению заметок
```

## Поиск источников

1. Просмотреть метаданные и содержание документов ядра в `notes/*.adoc`.
2. Искать релевантность по заголовку, `:description:`, `:keywords:`, `:type:` и полному тексту.
3. Для основной статьи использовать релевантные документы типов `note` и `topic`.
4. Документы с `:deprecated:` не использовать, кроме случаев, когда пользователь прямо просит исторический обзор.
5. `diary`, `index` и `list` не использовать как основные источники, если пользователь не попросил об этом явно.
6. Собрать достаточно широкий набор заметок, затем исключить случайные совпадения и дублирование.
7. Не придумывать факты, которых нет в заметках. Неясности формулировать как гипотезы или открытые вопросы.

## Обработка Memo и Todo

1. Отдельно найти релевантные документы типов `memo` и `todo`.
2. Не смешивать содержащиеся в них идеи и задачи с уже реализованными возможностями или подтверждёнными выводами основной статьи.
3. Если релевантные Memo или Todo найдены, сделать из них краткий обзор планов.
4. Добавить этот обзор в самом конце черновика под точным заголовком:

```markdown
## Планы по данной теме
```

5. Раздел планов должен быть последним содержательным разделом статьи.

## Подготовка черновика

1. Синтезировать связный авторский черновик, а не простую склейку заметок.
2. Сохранить идеи, терминологию и позицию пользователя.
3. Устранять повторы и явно разделять текущее состояние, наблюдения, гипотезы и планы.
4. Использовать Markdown, совместимый с Obsidian.
5. Предпочитать ясную структуру с H2/H3-заголовками, короткими абзацами, списками и кодовыми блоками при необходимости.
6. Перед разделом планов при необходимости добавить раздел `## Источники из Zettelkasten` со списком использованных заголовков и имён `.adoc` файлов. Если существует раздел планов, источники всегда должны располагаться перед ним.

## Имя и запись файла

1. Создавать файл в каталоге `Obsidian article drafts vault`.
2. Для первого черновика использовать точную тему пользователя как имя файла с расширением `.md`, заменяя только символы, недопустимые в имени файла.
3. Если файл уже существует, не перезаписывать его молча. Создать новый файл с суффиксом текущих даты и времени, если пользователь явно не попросил обновить существующий черновик.
4. Не изменять `.obsidian` и другие файлы Vault.

## Проверка результата

Перед завершением проверить:

- H1 совпадает с предложенной пользователем темой;
- файл является валидным читаемым Markdown;
- основные утверждения основаны на Note/Topic;
- релевантные Memo/Todo отражены только как планы;
- `## Планы по данной теме`, если добавлен, находится в конце;
- Zettelkasten не изменён;
- существующие статьи не перезаписаны без явного разрешения.

В ответе пользователю указать путь созданного Markdown-файла и кратко перечислить использованные группы источников.
