# zettelkasten-morning-thoughts

## Назначение

Обрабатывать присланную пользователем расшифровку утренних мыслей как секретарь: отделять самостоятельные мысли, систематизировать тезисы и планы, ранжировать их, атрибутировать по каналам и карьерным направлениям, затем сохранять каждую самостоятельную мысль отдельным Memo в Zettelkasten.

## Когда применять

Применять, когда пользователь присылает расшифровку утренней голосовой заметки или явно просит разобрать и зафиксировать утренние мысли.

Навык работает с уже предоставленной расшифровкой. Не утверждать, что аудио было расшифровано, если пользователь прислал только текст.

## Зафиксированный рабочий промпт

Использовать следующий промпт без изменений до тех пор, пока пользователь явно не попросит изменить его в этом навыке:

> Привет! Это проект для хранения и систематизации моих утренних мыслей. Действуй как секретарь. Систематизируй и выделяй основные тезисы и планы на будущее, выделяй отдельные темы для каждого чата в этом проекте. Сейчас у меня три чата: "Сучья фабрика", "Демон Максвелла" (мой персональный канал) и SA Larva — мой англоязычный канал. Выделяй отледьно темы для каждого из каналов (я проговариваю, куда какая тема идет)
> Еще нужно выделять и отделять от заметок и тем для каналов информацию о моем трудоустройстве и написании резюме (аналитика, backend-инженера и архитектора в будущем с уклоном в AI).

## Обязательная основная Topic

Каждый созданный Memo обязательно привязывать к:

`link:234b3986-61d2-11f1-8e5e-6b4ba23eb577.adoc[Утренние мысли - ключевая тема]`

Путь Topic:

`/Users/steamtoad/zettelkasten/notes/234b3986-61d2-11f1-8e5e-6b4ba23eb577.adoc`

Перед созданием Memo проверить, что Topic существует, не deprecated и имеет `:type: topic`.

## Разделение мыслей

1. Прочитать расшифровку целиком и определить общий контекст.
2. Разделить текст на самостоятельные мысли по смыслу, а не только по абзацам.
3. Если одна мысль повторяется в разных местах, объединить её в один Memo.
4. Если один фрагмент содержит несколько самостоятельных идей, создать несколько Memo.
5. Не смешивать в одном Memo:
   - идеи для разных каналов;
   - карьеру и трудоустройство с контентом каналов;
   - независимые планы или тезисы.
6. Не придумывать отсутствующие факты, сроки, назначение канала или намерения пользователя.
7. Если атрибуция неоднозначна, отметить это в Memo и выбрать категорию `Не определено`, не задавая лишний уточняющий вопрос.

## Категории атрибуции

Для каждой мысли определить одну основную категорию:

- `Сучья фабрика` — только если пользователь явно относит мысль к этому каналу;
- `Демон Максвелла` — только если пользователь явно относит мысль к персональному каналу;
- `SA Larva` — только если пользователь явно относит мысль к англоязычному каналу;
- `Трудоустройство и резюме` — поиск работы, резюме, позиционирование и карьерные действия;
- `Развитие роли: аналитик`;
- `Развитие роли: backend-инженер`;
- `Развитие роли: архитектор с уклоном в AI`;
- `Личная или общая мысль`;
- `Не определено`.

Карьерную мысль всегда отделять от идей для каналов, даже если они находятся рядом в расшифровке.

Допускается указывать вторичные категории, но у каждого Memo должна быть одна основная категория.

## Ранжирование

Назначить каждой мысли приоритет:

- `Высокий` — явно срочная, конкретная, повторяющаяся или непосредственно ведущая к действию мысль;
- `Средний` — полезная идея или план без явной срочности;
- `Низкий` — наблюдение, гипотеза или идея для дальнейшего обдумывания.

Не превращать эмоциональную выразительность речи в высокий приоритет без содержательного основания.

## Правила создания Memo

Создавать Memo напрямую по модели `zt-memo.zsh`, не запускать интерактивный Vim для каждого Memo.

Для каждого Memo:

1. Создать UUID v1 и использовать его как имя файла.
2. Использовать заголовок:

   `Memo - Утренние мысли: <краткое описание> от DD-MM-YYYY`

3. Добавить обязательные атрибуты:
   - `:date: YYYY-MM-DD`;
   - `:generated-at: YYYY-MM-DD`;
   - `:keywords:`;
   - `:type: memo`;
   - `:author: marta`;
   - `:description:` с полным заголовком;
   - `:doclink:`;
   - `:docfilename:`;
   - `:key-topic: Утренние мысли`.
4. Наследовать keywords основной Topic по правилам `zt-memo.zsh`: добавить `memo`, исключить `topic`, не создавать дубликаты.
5. Добавить только полезные атрибуционные keywords по содержанию, например `morning-thoughts`, `sf`, `demon-maxwell`, `sa-larva`, `employment`, `resume`, `system-analysis`, `backend`, `architecture`, `ai`.
6. Добавить двустороннюю связь по правилам `zt-memo.zsh`:
   - в Memo раздел `== Связи` и ссылку с меткой `Topic` на Topic утренних мыслей;
   - в Topic раздел `== Связанные memo` и ссылку на Memo;
   - не создавать дублирующиеся ссылки или заголовки.
7. Зарегистрировать Memo в `all-todays/YYYY-MM-DD.adoc`.

## Структура содержимого Memo

Использовать структуру:

```asciidoc
== Краткая формулировка

Краткая очищенная формулировка мысли.

== Основные тезисы

* Тезис.

== Планы и следующие шаги

* Конкретный план или `План не сформулирован`.

== Атрибуция

* Основная категория: ...
* Вторичные категории: ...
* Приоритет: Высокий / Средний / Низкий
* Уверенность атрибуции: высокая / средняя / низкая

== Исходный фрагмент расшифровки

Релевантный исходный фрагмент без добавления новых смыслов.
```

Не создавать пустые списки. Если план отсутствует, написать это явно одной строкой.

## Связи с существующими темами

После обязательной привязки к Topic утренних мыслей найти активные существующие Topic, Memo или Note, непосредственно соответствующие содержанию мысли.

- Сначала искать по `:key-topic:`, `:keywords:`, `:description:` и заголовкам.
- Предпочитать сильные смысловые совпадения и недавние релевантные документы.
- Добавлять ограниченное число полезных двусторонних кросс-ссылок.
- Не менять основной `:key-topic: Утренние мысли`.
- Не связывать документы только из-за общего слова или слабого совпадения.
- Не связывать с deprecated-документами.

Для идей каналов можно связывать с соответствующими существующими Topic, если совпадение подтверждено. Карьерные мысли связывать с карьерными заметками отдельно от каналов.

## Проверка и отчёт

После создания всех Memo:

1. Проверить обязательные метаданные, UUID, `:key-topic:` и ссылки.
2. Проверить, что каждая самостоятельная мысль сохранена ровно в одном Memo.
3. Проверить, что мысли разных каналов и карьерные мысли разделены.
4. Запустить `zt-check`.
5. Показать краткий отчёт:
   - сколько Memo создано;
   - распределение по основным категориям;
   - распределение по приоритетам;
   - ссылки на созданные Memo;
   - результат `zt-check`.

## Безопасность

- Не изменять зафиксированный рабочий промпт без явной просьбы пользователя изменить его в навыке.
- Не изменять скрипты Zettelkasten при обработке расшифровки.
- Не создавать Topic автоматически вместо отсутствующей тематической связи.
- Не помечать существующие документы deprecated.
- Не переименовывать существующие UUID и файлы.
- Не терять исходный смысл при очистке спутанной речи.
